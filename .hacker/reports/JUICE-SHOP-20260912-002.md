## 2. Execucao

Metodologia: scan passivo e ativo em aplicacao web vulneravel em container Docker
local. Duas ferramentas DETERMINISTICAS do gate web-scan: ZAP (spider + active scan)
e Nuclei (DAST + exposicao). Saida intermediaria JSON conforme regra 1.3.

Comandos reais executados:

```bash
# ZAP daemon (imagem oficial atual; owasp/zap2docker-stable foi descontinuada)
docker pull ghcr.io/zaproxy/zaproxy:stable
docker run -d -p 8080:8080 --name zap-juice -v /tmp/opencode/zap-wrk2:/zap/wrk \
  ghcr.io/zaproxy/zaproxy:stable zap.sh -daemon -host 0.0.0.0 -port 8080 \
  -config 'api.addrs.addr.name=.*' -config 'api.addrs.addr.regex=true' -config 'api.disablekey=true'
# saida: {"version":"2.17.0"} na API

# spider + active scan via API REST
curl -X POST -H 'Content-Type: application/x-www-form-urlencoded' \
  --data 'url=http://172.17.0.1:3000' http://localhost:8080/JSON/spider/action/scan/
# saida: {"scan":"0"}; status final: {"status":"100"}; 88 URLs coletadas
curl -X POST -H 'Content-Type: application/x-www-form-urlencoded' \
  --data 'url=http://172.17.0.1:3000&recurse=true' http://localhost:8080/JSON/ascan/action/scan/
# saida: {"scan":"0"}; status final: {"status":"100"}

# relatorios ZAP
curl -s 'http://localhost:8080/OTHER/core/other/xmlreport/?formMethod=GET' -o zap-report.xml
curl -s 'http://localhost:8080/OTHER/core/other/jsonreport/?formMethod=GET' -o zap-report.json

# Nuclei (templates direcionados misc/exposure/config)
nuclei -u http://localhost:3000 -jsonl -o nuclei-20260912.jsonl -tags misc,exposure,config
# saida final: "Scan completed in 33.55s. 8 matches found."
```

## 3. Escopo

- **Scanado**: aplicacao web Juice Shop (versao 20.2.0, detectada via metricas) na
  porta 3000 local. ZAP: spider (88 URLs) + active scan completo (status 100%).
  Nuclei: 1550 templates do grupo misc/exposure/config.
- **Nao scanado**: hosts externos, testes de autenticacao manual, testes de logica
  de negocio, categorias Nuclei fora do grupo selecionado.
- O scan foi totalmente local (alvo loopback). Nenhuma conexao saiu da maquina.

## 4. Metodologia

1. Inicio do ambiente (container ZAP + target Juice Shop local).
2. Verificacao de disponibilidade (HTTP 200 em `http://localhost:3000` e do ZAP no gateway docker).
3. Spider ZAP (descoberta de 88 URLs).
4. Active scan ZAP (status 100%) com regras passivas e ativas.
5. Exportacao dos relatorios ZAP em XML e JSON (artefatos intermediarios).
6. Scan Nuclei com templates misc/exposure/config, saida JSONL.
7. Consolidacao de findings e classificacao CVSS v3.1/CWE a partir de metadados dos templates.
8. Registro no ledger operacional.

## 6. Conclusao

O scan combinado ZAP + Nuclei (lab local, alvo loopback) encontrou 1 finding medium
partilhado que ja era conhecido do escopo anterior (exposicao de metricas Prometheus,
FIND-NUCLEI-20260912-001) e acrescentou 2 medium vindos do ZAP (CSP header ausente,
CORS permissivo). Demais achados sao informational. Nenhum high ou critical foi
detectado pelas duas ferramentas neste escopo.

Destaques para correcao, em ordem de prioridade:
1. Expor `/metrics` (FIND-NUCLEI-20260912-001, medium).
2. Ausencia de CSP (FIND-ZAP-20260912-001, medium).
3. CORS `Access-Control-Allow-Origin: *` (FIND-ZAP-20260912-002, medium).

Riscos residuais: o Juice Shop contem vulnerabilidades propositais de logica de
negocio e injecao que nao sao detectadas por scan automatizado; testes manuais
orientados (SQL injection, broken access control, XSS) ficam como proximo passo
autorizado quando o Fernando solicitar.

Proximos passos sugeridos:
1. Registrar ledger operacional (feito, OP-20260911-009).
2. Rodar suite de validacao `validar-scan-web.sh` apos fechamento.
3. Testes manuais direcionados por categoria OWASP (sob nova autorizacao).
4. Parar containers ao fim do lab: `docker stop zap-juice juice-shop`.
